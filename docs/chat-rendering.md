# 对话渲染与刷新

## 2026-10-15 分离模型响应和运行总时限

问答、需求评审和协同补充回答不再共用 3 分钟总时限。默认规则：

- 每次模型请求等待首次有效内容最多 3 分钟；HTTP 响应头、空片段和连接心跳不算有效内容。
- 收到内容后切换到流式无响应计时，每次非空文字、工具参数或模型思考增量都会刷新 3 分钟计时；监测仅转发活动信号，不额外展示或记录思考内容。
- 整次 Agent 运行最多 30 分钟，包含准备上下文、工具执行、模型请求、SDK 重试和上下文压缩。持续输出可以超过原来的 3 分钟，但仍受独立总时限约束。

计时跟随 Pi 实际提供方流的开始与结束。工具执行期间没有模型无响应计时；工具结束后的新模型请求重新等待首次内容，SDK 的压缩请求也监测真实内容。标题生成沿用独立的 12 秒限制。

超时保存已有回答和过程，并明确显示「模型首次响应超时」「模型流式响应超时」或「分析达到总时限」；手动停止仍标记为停止。协同超时属于失败，沿用现有至多 3 次总尝试的自动重试，重试保留上次可见文字到过程区；调查结果本身不变。

启动参数分别为 `-agent-first-response-timeout 3m`、`-agent-stream-idle-timeout 3m`、`-agent-total-timeout 30m`，均须大于 0。默认值不需要额外配置。

隔离阅读保留独立的 2 分钟源码准备时限，runner 的容器总时限默认改为 35 分钟，避免先于平台 30 分钟总时限中断运行。自定义更长的平台总时限时，应同步提高 runner 的 `-worker-timeout`。

测试包括虚拟时间下持续输出 29 分钟不被截断、30 分钟总时限、首次内容/输出中断、工具间隔、手动停止；真实 Pi SDK 对本地模型测试端点验证空片段不刷新时限、超时中止上游连接和部分回答持久化。仅本地验证，尚未部署。

## 2026-10-15 保留过程并折叠

原来所有助手消息累加在 `output`，运行结束后又被最后一条回答覆盖，因此工具调用前已展示的说明会消失。现在 Pi worker 转发公开助手消息的开始边界：新消息开始时，上一条文字移入 `process_output`，`output` 保留当前回答。过程与回答一起保存到 SQLite；SSE 分别增量传输两者，`output_version` 防止旧存盘快照在消息切换时把已归档的说明重新塞回回答。

回复上方的「思考过程」收纳已显示的中间说明和工具调用状态，运行中默认展开，完成、失败或停止后默认折叠。用户之后可以点击或用键盘展开；后台刷新尊重手动展开/收起状态，最终回答始终显示在折叠框外。刷新页面后，保存的过程仍可查看。模型思考配置保持不变。

旧记录没有 `process_output` 时继续正常显示最终回答；已有工具记录可折叠查看，本次未回填历史上被覆盖的过程文字。验证覆盖真实 Pi 多轮工具调用与持久化、消息边界与 SSE 增量合并、后台旧快照、完成后自动收起、手动展开、停止/失败、刷新恢复及移动端。浏览器入口仍为 `internal/web/stream.browser-check.mjs`。此修复尚未部署。

## 2026-10-14 连续输出优化

原来的模型增量先等约 300 毫秒存盘，再由浏览器每 900 毫秒读取，文字会按批次跳出来。现在通过同源 `GET /api/runs/{id}/events` SSE 连接推送实时输出，存盘节奏保持独立。首条消息和重连使用完整快照，后续只传新增文字；最终回答发生替换时发送新快照。服务端最多每 40 毫秒合并推送一次，客户端按动画帧更新现有节点。

慢客户端只保留一个待处理通知，不阻塞模型；连接每 10 秒检查最新状态和权限并发送心跳。读取保留会话归属、删除、手动标题和协同取消规则，完成/停止时先存盘再结束连接。项目切换、会话删除和登录过期会关闭旧连接。每个运行最多一个更新循环，最多同时四条 SSE 连接；连接失败时回退原轮询，10 秒后尝试恢复实时推送。后台存盘快照落后于实时文本时不会让文字倒退。

验证使用隔离数据库和本地输出程序，不访问真实模型或生产数据：

- Go 测试覆盖存盘前可见、慢消费者合并、快照隔离、归属/删除/手动标题、真实 HTTP 增量、断线重连及最终持久化。
- `internal/web/stream.browser-check.mjs` 跑实际 Go → SSE → Chromium 链路。输入每 60 毫秒一段文字时，1.1 秒观察到 19 次页面更新，中位间隔约 74 毫秒，正常输出期间单运行轮询请求为 0。
- 浏览器验证底部跟随、向上阅读、草稿/焦点/选区保留、断线后回退并重连、停止保存、刷新恢复和 390px 视口；既有 Markdown/协同结果浏览器检查通过。

复现：先 `go build -o bin/ai-pm-chat-check ./cmd/server`，再运行 `node internal/web/stream.browser-check.mjs`；按需用 `AI_PM_QA_NODE_MODULES` 指定 Playwright 所在目录。结果保存在 `test-results/chat-stream/checks.json`。上述间隔仅为本地模拟输出测试，真实模型的首字时间和生成速度取决于提供方。此优化尚未部署。

## 2026-10-12 修复

旧版把 Agent 输出转义后作为纯文本插入，Markdown 的标题、列表和加粗标记因此直接显示。每 900 毫秒的运行轮询会替换整条回复，每 6 秒的后台刷新还会重建整个应用并重新触发页面入场动画，导致持续对话期间闪烁。

新版在客户端使用内嵌的 Marked 18.1.0 解析 Markdown，再经 DOMPurify 3.4.16 净化；原始 HTML 按文本显示。支持标题、加粗、列表、行内代码、代码块、表格、链接和引用。第三方库版本、来源、完整性信息与许可证保存在 `internal/web/static/vendor/`，浏览器不加载外部 CDN。

问答页面按运行 ID 保留消息节点，运行轮询只更新变化的文本、状态、工具记录和操作按钮。页面、输入框和未变化的回复节点不会被重建；后台刷新不会重新触发入场动画。停留在回复底部时跟随更新，向上阅读历史时保留当前位置。每个运行只有一个轮询循环；较慢的后台响应不会覆盖期间收到的新输出。
