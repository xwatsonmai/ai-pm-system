# 待办与消息推送

有人需要处理的事项会成为**待办**，推送给对应的产品、开发或测试。通过、确认这类操作可以在 IM 卡片里直接点；需要填写内容时，卡片打开待办页面，电脑和手机都能用。IM 以插件（渠道）接入，目前内置企业微信。

## 项目角色

项目成员可以同时担任多个角色，由项目管理员或平台管理员在成员管理里勾选。

| 角色 | 收到的待办 |
| --- | --- |
| 产品 | 评审回复、需求稿确认、驳回确认、开发对齐回复、验收 |
| 开发 | 待认领、待上线 |
| 测试 | 待测试、待复测、Bug 修复待验证 |
| 管理员 | 不单独接收待办；可以添加、移除成员和分配角色 |

- 角色只决定推送给谁，不改变业务权限。除成员管理外，项目成员的协作能力相同。
- 项目里没有人勾选「测试」时，测试类待办发给产品。这与之前由产品测试的做法一致，适合没有专职测试的团队。
- 评审、对齐和验收优先发给需求创建人（仍是项目成员时），否则发给全部产品；待上线优先发给认领的开发。
- 旧数据中的单个 `role` 读取时自动转成 `roles`，不需要迁移。接口 `PUT /api/projects/{id}/members/{user}` 接受 `{"roles": [...]}`，也兼容旧的 `{"role": "..."}`。

## 待办

待办由需求的当前状态推导，不依赖某个操作是否发过通知：

| 待办 | 何时出现 | 卡片按钮 |
| --- | --- | --- |
| 需求评审等你回复 | 评审 Agent 提问，等产品回答 | 打开页面回答 |
| 需求稿待确认 | 评审给出需求稿 | 确认需求稿（需要复核时只能打开页面） |
| 评审建议驳回 Bug | 评审认为 Bug 不成立 | 同意驳回 |
| 开发对齐等你回复 | 开发代理请求对齐 | 打开页面回复 |
| 有需求待认领 | 需求进入待认领 | 打开页面查看 |
| 待测试 | 开发提测 | 测试通过（需求的「提起 Bug」和平台 Bug 的「退回」在页面里） |
| 待复测 | 关联 Bug 全部处理完 | 打开页面填写复测版本 |
| Bug 修复待验证 | 关联 Bug 提交修复 | 验证通过 |
| 测试通过，待上线 | 测试通过 | 打开页面登记上线 |
| 已上线，待验收 | 登记上线 | 验收通过（逐项确认全部条件）；不通过在页面里填写原因 |

- 任何服务端写入（工作台、个人 MCP、卡片、平台 Agent）提交后，都会重新推导该需求的待办。服务启动时和每 10 分钟还会全量核对一次，即使进程在写入后、推送前退出，待办也不会丢。
- 同一件事等待期间，待办保持不变；事项结束后待办关闭，并记下「已由 某某 处理」。同一件事之后又回来等待（例如需求退回重新认领），会生成新的待办。
- 卡片按钮以绑定的成员身份执行，走与工作台相同的接口、权限和版本检查。卡片按点击时的最新状态判断：内容已变化（例如开发重新提测）时不会执行，卡片提示打开详情处理。同一张卡片重复点击不会重复执行。
- 卡片上「测试通过」使用卡片显示的版本和环境，测试说明记为「通过消息卡片确认」；需要写明证据时，请在页面里提交。

### 待办页面

- `/todo`：我的待办（待处理 / 已处理），以及消息通知的绑定状态。
- `/todo/<id>`：处理一项待办。评审和对齐类直接打开评审群聊；测试、验证、上线、验收显示对应表单；已结束的待办显示处理结果。
- 工作台右上角的「我的待办」进入同一页面；页面里的「在工作台查看」通过 `/?task=<id>` 打开对应需求。
- 不配置任何 IM 渠道时，待办页面同样可用。

## 企业微信

### 准备

1. 在企业微信管理后台创建自建应用，设置成员可见范围。
2. 平台管理员在「平台设置 → 消息推送 → 企业微信 → 配置」填写：

| 配置 | 位置 |
| --- | --- |
| 公网地址 | 企业微信服务器回调和成员打开待办都使用这个地址。留空时使用平台访问地址（`auth.json` 的 `public_url`） |
| 企业 ID | 我的企业 → 企业信息 |
| 应用 AgentId、Secret | 应用管理 → 自建应用 |
| 接收消息 Token、EncodingAESKey | 应用 → 接收消息 → 设置 API 接收 |
| 接口地址（可选） | 通过代理访问企业微信接口时填写 |

3. 保存后，配置窗口会列出需要回填到企业微信后台的值：接收消息 URL（`<公网地址>/integrations/wecom/callback`）、网页授权及 JS-SDK 可信域名、企业微信授权登录的 Web 回调域名、应用主页（`<公网地址>/integrations/wecom/entry`），以及企业可信 IP（服务器访问企业微信接口时的出口 IP）。
4. 管理员先在「我的待办」绑定自己，再点「发送测试消息」确认推送可用。

Secret、Token 和 EncodingAESKey 用 `repository.key` 加密保存，接口和页面只显示「已配置」。留空保存表示保留原值。消息推送需要成员登录，未配置 `auth.json` 时不能启用。

### 网络要求

- 发送消息：服务器能访问企业微信接口，出口 IP 已加入应用的企业可信 IP。
- 卡片按钮：企业微信服务器要能访问 `<公网地址>/integrations/wecom/callback`。
- 打开待办：成员的手机或电脑要能访问公网地址。网页授权要求公网地址的域名是应用的可信域名（企业微信通常要求已备案，且与企业主体相关）。

公网地址的主机会加入服务接受的主机列表。反向代理需要原样转发 `Host` 头。公网地址与平台访问地址不同时，最好让两者指向同一个服务；使用外部登录（如统一登录）时，登录仍会跳到平台访问地址，此时请成员先在公网地址上绑定一次，之后即可免登录进入。

### 绑定与免登录

成员不需要知道、也不需要填写自己的企业微信账号，有两种方式：

- **从平台拉起企业微信**：在「我的待办」点「绑定企业微信」。在企业微信内置浏览器里静默授权；在普通浏览器里打开企业微信登录页，电脑上可以用「企业微信快速登录」拉起本机客户端，也可以扫码。
- **从企业微信拉起平台**：打开应用主页或任意卡片，静默授权。如果这个企业微信账号还没有绑定，成员登录一次平台后自动绑定，并回到原来要打开的页面。

绑定后，从企业微信打开卡片或应用主页时直接以绑定的成员进入（可在配置里关闭「免登录」）。内置账号停用后不能再免登录进入，卡片操作也会被拒绝。一个企业微信账号只能绑定一位成员；成员可以在「我的待办」解除绑定。

授权状态只在发起它的浏览器里有效，10 分钟内使用一次。

### 卡片

- 有按钮的待办发「按钮交互型」模板卡片，其他发「文本通知型」卡片。卡片只包含项目名、需求标题、待办说明和版本、环境等关键字段，不包含需求正文。
- 待办结束后，72 小时内发出的按钮卡片会更新为「已由 某某 处理」，点击者的卡片显示点击结果。
- 发送失败按 1 分钟、5 分钟、15 分钟、1 小时、3 小时重试，第 6 次失败后放弃。渠道停用期间，待发卡片保留到重新启用。
- 成员绑定后，会补发近 7 天内仍未处理的待办。

## 扩展边界

渠道插件在 `internal/notify` 注册，核心不依赖具体 IM：

```go
notify.Register("name", notify.Spec{Label: "飞书", Fields: ..., Setup: ..., Open: open})
```

- `Spec.Fields` 声明配置项（`Secret` 字段加密保存），平台设置页面据此生成表单；`Spec.Setup` 列出需要回填到 IM 后台的值。
- `Open` 返回 `notify.Channel`：
  - `Send` / `Update`：发送卡片，结束后更新为最终状态。不能更新时返回 `notify.ErrNotUpdatable`。
  - `Callback`：接收 IM 的事件推送，把按钮点击交给核心处理，并返回点击者应看到的卡片。
  - `AuthorizeURL` / `Identify`：网页授权，用于绑定和免登录。
- 核心负责待办推导、收件人、发件状态与重试、绑定、免登录、按钮权限与幂等。渠道只负责 IM 的协议和卡片格式。
- 渠道路由固定为 `/integrations/<name>/{entry,bind,oauth,complete,callback}`。

渠道在 `cmd/server/channels.go` 注册。私有部署也可以只新增文件，在 `cmd/server/` 下另加一个文件注册自己的渠道。
