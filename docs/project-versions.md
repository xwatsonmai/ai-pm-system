# 并行项目版本与项目时间线

项目版本是独立推进的交付里程碑，与需求内容修订 `revision`、并发编号 `version` 分开。一个项目可以有多个进行中（`active`）版本；`current_milestones` 只指向接收新需求的**默认版本**，不再限制进行中版本数量。列表和详情的 `is_default` 表示默认归属，旧 `current` 字段保留为同义兼容字段。默认指针的并发编号在 `default_version` 返回，与某个版本自身的 `version` 分开。

## 产品操作

- 每条新需求和独立 Bug 都必须归属一个版本。创建表单可搜索并分页选择进行中版本；从版本详情创建时预选该版。未指定目标的旧客户端、问答建单和追加迭代继续进入默认版；项目没有任何进行中版本时，在保存需求的同一事务自动创建默认版。多个进行中版本而没有默认时必须明确目标，不能任意猜选。
- 可随时创建并行版本，填写名称、目标、负责人、计划完成日期；同一项目名称不可重复。首个进行中版本自动成为默认，之后新建、开始或重新打开其他版本不会抢占默认。可明确「设为默认版本」，这只改变新需求去向，不移动既有需求。
- 各版本独立开发、测试、登记上线、验收和结束。一次上线不结束版本，也不冻结范围；历史发布快照始终保留。允许版本并行不代表平台执行部署、自动分支合并或自动提供多个线上环境。
- 需求池按版本筛选；尚未结束、未上线的需求可填写原因移入任意进行中版本，不能移回未排期。关联需求及其未结束 Bug 会一起调整，已上线的待验收需求留在原版。
- 全部需求已验收、解决或明确结束后显示「待结束」，由产品「结束里程碑」填写结论。拒绝、关闭、取消和已解决 Bug 单独统计，不能当作需求业务验收通过。结束默认版时选择后继默认版；仅剩一个进行中版本可自动接任，没有则留空。
- 「关闭里程碑」选择剩余开发工作的目标进行中版本，或明确创建后继版本。需求状态、原认领和分支保留，待验收需求继续留旧版；其他并行版本不受影响。关闭默认版时目标同时接任默认。旧客户端省略目标且只有唯一可确定去向时兼容处理，有多个候选则要求明确选择。
- 已结束版本可填写原因重新打开，与其他版本并行。已结束版本中的需求被重新打开、验收退回或继续修订时，后续工作进入指定或默认进行中版本，旧交付证据保留。任务动作可通过 `destination_version_id` 指定后续目标。
- 测试/验收 Bug 跟随父需求版本，不能随项目默认变化跨到无关版本。父需求所在版已结束时，提起验收 Bug 会把父需求的后续修复与新 Bug 原子归入所选版本，旧发布快照仍保留原修订、分支、SHA 和交付结果。

## 发布与历史

开发完成仍进入「待上线」。实际部署成功后，「登记本次已上线」要求逐项勾选需求，并填写实际环境和证据。没有默认全选，只推进选中项进入待验收，不执行部署。每项核对目标版本、最新并发编号、修订和提交 SHA；任一冲突则整批不保存。

每次上线保存完整需求、附件元信息、开发提交、环境和证据快照；后续修订与验收只更新当前范围，不改写发布快照。需求在同一里程碑内修改后，范围跟随最新修订，旧上线记录仍可追溯；新修订必须重新开发、提交和登记上线。

## 项目时间线

「项目时间线」把所选范围画成一条从「出发」走向终点箭头的路线，按时间顺序从左到右排列，到页面边缘圆角折返、下一行反向前进（蛇形）。路线按时间段分节点，工具栏可选每 2 小时、每半天或每天一个节点，切换只重排已加载的数据；切换 7/30/90 天范围时分别默认 2 小时、半天、每天。每段开头的大节点是这段时间的起点，当天第一个节点标出日期，其余只标钟点；其后的小节点按时间排列：路的上沿是需求节点（按步骤着色），下沿是这段时间的全部 Git 提交，时间相近的节点合并，悬停可看明细。路线上方是需求卡片：每个需求在每个节点只出现一次，显示这段时间走到的最远一步（新建、确认、开始处理、开发完成、上线、验收、关闭或退回），卡片底部写出它从提出到上线、验收的日期；归入里程碑等整理类事件不上图。悬停或聚焦卡片时，会点亮这个需求在路上的全程（范围前已提出的从「出发」开始，尚未结束的延伸到箭头），把它被折叠在「+N 个需求动态」里的其他状态换到可见位置，并在卡片上方弹出完整变更历史（时间、步骤、操作人与说明，含归入里程碑等整理类记录）。路线下方是里程碑旗标（开始、登记上线、结束等）和提交列表；提交较多时列表每个节点抽取 3 条，优先关联需求的提交并均匀取样、跳过合并提交，「+N 条提交」可在原地展开全部，需求卡片超过 4 张时同样折叠。没有记录的日子不占位置，路上画断开标记，日期旁标出「隔 N 天」。可以查看最近 7/30/90 天、切换截止日期和加载更多记录；行宽随页面自适应，手机上每行一个节点。点击需求、里程碑或提交查看详情。

需求起止与当前修订的开发提交、上线时间独立于事件分页返回，避免首屏缺少创建或完成事件而画错持续时间。完成时间读取当前修订的验收记录；关闭、拒绝和取消读取决定记录，不使用最近更新时间代替完成时间。缺少历史时间时明确标注，不推测完成。所选历史范围会裁去范围之外的节点，未到完成时间的路线继续显示。

Git 记录来自已经同步的本地仓库，查看页面不会触发远程拉取。仓库未连接、未同步或读取失败会明确提示，不能当成没有提交。提交时间使用 Git 提交者时间。仅当前开发提交和历史发布快照中的完整 SHA 精确匹配时，才标记关联需求，不根据时间或标题推测关联。需求事件和 Git 分别分页，翻页保持相同截止时间和 Git 分支快照。

## 保存与重试

需求内容、目标版本归属、范围、历史事件和回执原子保存，避免保存了需求却没有版本。保存成功后关闭创建窗口，后台独立评审；评审失败不回滚原文、截图、附件或补充。

版本表单的输入与勾选状态按用户、项目、表单暂存在当前浏览器。提交前保存完整请求和 `request_id`，网络结果不明时锁定原请求并原样重试。「核对保存结果」可以取得原回执，不重复创建或推进。明确冲突时保留输入，核对最新事实后使用新请求 ID。浏览器存储不可用时仍可在未关闭的表单内重试，不承诺跨浏览器恢复。

## API 与迁移

| 路径 | 操作 |
| --- | --- |
| `GET /api/projects/{id}/milestone` | 默认版本（旧完整详情形状），没有时返回 null；读取不会创建 |
| `GET/POST /api/projects/{id}/versions` | 所有版本摘要的筛选分页 / 创建并行版本 |
| `GET /api/projects/{id}/version-options[/{version}]` | 需求表单使用的轻选项，仅 ID、名称、状态、版本号和默认标记 |
| `GET/PUT /api/project-versions/{id}` | 旧完整详情 / 修改计划；`GET ?summary=1` 仅计划与全范围统计 |
| `GET /api/project-versions/{id}/scope` | 范围分页，可按状态过滤、包含已移出需求 |
| `GET /api/project-versions/{id}/releases` | 发布记录分页，不捎带全部需求正文 |
| `GET /api/project-versions/{id}/releases/{release}/tasks` | 某次发布的不可变需求快照分页 |
| `GET /api/project-versions/{id}/history` | 范围与计划变更历史分页 |
| `POST /api/projects/{id}/version-assignments` | 将需求及未结束关联 Bug 调整到目标进行中版本 |
| `POST /api/project-versions/{id}/actions` | start、publish、complete、close、reopen、set_default |
| `GET /api/projects/{id}/timeline` | 需求事件和 Git 提交的同轴时间线 |

版本列表显式传 `page` / `page_size` 返回 `{items,total,page,page_size}`，默认每页 20、最多 100；`q` 搜索名称或目标，`status` 筛选 active/planned/completed/closed。旧无参数调用继续返回摘要数组。范围、发布记录、发布快照需求及历史独立分页，列表数量、进度统计基于完整筛选范围，不按本页推算。范围 `include_removed=true` 包含已移出项，`status=pending_release` 用于发布选择器；跨页勾选保留已选 ID，单次最多登记 100 项。读取版本管理详情、范围和历史需要版本页面访问；需求表单的轻选项不包含目标、统计或交付文档。

创建可用 `set_default:true` 设置默认，`set_default` 动作携带目标 `version` 和最新 `default_version`。关闭/结束可携带 `destination_version_id` 与最新 `destination_version`；关闭显式新建后继使用 `create_successor:true`。仅修改实际默认指针时递增其并发编号，其他版本动作不会争用全项目指针；默认归属读校验、版本与需求 CAS、事件及幂等回执仍在同一事务内。

写入要求唯一 `request_id`，更新/动作携带最新 `version`；批量调整核对每个需求版本；发布额外核对每项 `revision` 和 `sha`。时间线参数 `from`/`until` 为毫秒，起点包含、终点不包含；`offset`/`git_offset` 分别分页，`git_anchor` 固定分支头，每页最多 200 项。

历史 SQLite schema 11 新增 `current_milestones` 和时间线索引。升级从旧版本中选取最近的未结束计划作为当前里程碑，其他计划保留为待开始，原计划、范围和发布快照不删除。缺少归属的旧需求（包括已验收、已关闭项）统一归入当前；没有当前版本时创建一个「默认版本」承载，不按阶段拆分历史需求。没有需求的空项目不预建版本。回填只修改归属、并发编号和更新时间，不改原文、内容修订、附件、状态或认领；升级仅执行一次。

本次并行功能不改写既有版本、需求归属或发布快照，也不重复执行 schema 11 回填；原当前版直接作为默认版。旧客户端仍能通过 `current_milestone` / `project_milestone_get` 读取默认版，创建时不传目标仍进入默认。新建多个进行中版本后，旧服务程序的单当前业务规则不再完整兼容；回退必须使用能识别并行数据的兼容版本，不能直接假定旧镜像可以继续管理这些数据。

MCP 同时提供产品需求与里程碑管理，不必先开发认领。所有产品写操作必须由用户明确要求，通过个人 OAuth 保存实际员工身份和授权原话。平台后台 Agent 仅可读取上下文、提交评审建议，不能自行代替产品确认或结束版本。详细参数见 [产品与开发 MCP](developer-mcp.md)。
