# 平台权限、项目角色与个人 MCP

独立菜单「我的 MCP」对每个登录成员开放，未分配项目也可以开通；授权时仅能选择自己已加入的项目。「平台设置」只对平台管理员开放，管理默认 Agent 模型、模型配置、平台管理员和全平台的成员项目授权；使用内置账号时还在这里管理平台账号。

项目角色为开发者（developer）、产品（product）和管理员（admin）。三者拥有同等业务能力，包括任务、验收、代码读取、问答和项目资料/仓库配置。领取需求属于开发工作，只能由开发代理通过开发 MCP 的 `task_claim` 进行；网页不提供领取，服务端也拒绝网页账号领取。网页可以用「交接任务」把处理中的需求退回待认领。项目管理员另外可以搜索成员目录、添加/移除成员和调整角色。平台管理员可以分配任意项目成员；访问项目业务数据及授权 MCP 也需加入项目。创建者不会在被移除或降级后保留特殊权限，项目至少保留一位管理员。

## 首批管理员与成员目录

`auth.json` 的 `platform_admin_login_ids` 列出首批平台管理员的登录名：内置账号填用户名，外部登录扩展填它提供的登录 ID。这些人登录后自动登记为平台管理员，配置保留期间不能在页面撤销；其他平台管理员由平台设置页面授予。使用内置账号时，首次初始化创建的账号直接成为平台管理员，见 [登录方式](login.md)。

成员目录由登录方式提供：

- 内置账号：列出全部未停用的平台账号。
- 外部登录扩展：可以提供自己的组织目录，例如带部门、岗位，并支持在成员首次登录前授权。
- 未提供目录时，从已登录过工作台的用户中选择。

新增项目成员或平台管理员时，会拒绝目录中已不存在或已停用的人。目录读取失败时返回明确错误，不会把失败当作空目录。

## OAuth 行为

客户端访问 `/mcp` 未授权时收到 401 和资源发现地址。平台提供资源/授权服务器元数据、公共客户端动态注册、浏览器确认授权、授权码兑换、刷新和撤销接口。

按产品要求，不联网读取客户端 ID 元数据文档、Logo、JWKS，不验证 software statement 或客户端 secret。动态注册忽略附加元数据字段；URL 形式及其他公共 client_id 可以直接发起授权。元数据声明 client_id_metadata_document_supported=false，支持该机制的客户端使用动态注册兼容流程。这是有意的客户端兼容策略，不宣称实现元数据文档验证。

用户身份、项目成员关系、HTTPS/本机 HTTP 回调、登记后的精确回调匹配、资源地址和 S256 PKCE 仍会校验。授权码 5 分钟内一次性使用，access token 有效期 1 小时，refresh token 授权期 30 天且每次刷新同时轮换两种令牌。刚被轮换的 refresh token 在 60 秒内仍可兑换新令牌对，用于刷新响应丢失后的重试，此前换出的令牌同时失效，宽限截止时间不因重试延长。数据库只保存令牌摘要；接口只在兑换时返回原始令牌，授权列表不返回令牌或摘要。

每个连接绑定一位员工与一个项目，MCP 每次请求重新校验个人开通状态及项目成员关系。成员移除后，下一次请求和刷新被拒绝；个人页面可撤销单个连接。关闭个人 MCP 在同一事务中删除所有授权和未兑换授权码，并推进开通版本，拒绝关闭前已在途的迟到授权；重新开通需重新授权。

## 升级与验证边界

SQLite 结构版本 5 自动增加平台权限与 OAuth 相关表。旧项目负责人对应管理员，旧成员对应开发者；旧资料无负责人时默认不向任意登录用户开放，需通过平台设置分配成员。迁移从最近一个已选模型的旧项目取平台默认模型，仅执行一次，后续项目不再选择模型。旧模型配置由平台管理员统一管理。

正式登录模式不再接受旧项目 MCP 令牌；客户端需改用个人 OAuth。免登录本机模式仅为现有开发集成保留旧令牌兼容。

自动回归覆盖三个角色的业务能力与权限限制、成员移除、平台模型设置、OAuth 发现与官方 SDK 接入、PKCE/资源/客户端绑定、换码一次性、刷新轮换和关闭授权。

验证命令：`make test`。浏览器脚本 `internal/web/chat.browser-check.mjs` 需要 Playwright，通过 `AI_PM_QA_NODE_MODULES` 指定已安装的包目录，`AI_PM_QA_BIN` 指定本次构建的二进制；截图保存在 `test-results/`（Git 忽略）。
