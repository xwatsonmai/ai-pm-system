# 版本谱系

项目需求菜单中的「版本谱系」以垂直关系图展示版本范围：版本为根，需求为同等大小的节点，子需求、关联 Bug 和追加迭代通过带文字的连线表达关系。独立需求和有子项的需求使用相同的视觉权重。

左侧版本目录显示完整范围中的需求、Bug 数量；画布中的完成率统计已验收需求和已解决 Bug。数量来自该版本未移除的范围快照，不受搜索、分页、展开状态影响。跨版本引用使用虚线，保留真实所属版本并提供跳转，不计入当前版本统计。

## 浏览与权限

- 版本目录每页 12 个版本，根需求每页 3 组，直接子项每次加载 4 项。末页失效时由服务端调整到有效页码。
- 搜索标题、编号或负责人时保留祖先路径；未命中的上级显示为上下文。只读取元数据，不传输正文、附件、评审内容或冻结的迭代原文。
- 默认展开两层。展开与收起、节点详情、版本切换、缩放、拖动、适应视图和总览定位均可直接操作。画布支持方向键、加减号和数字 0。手机默认以可读字号打开，可拖动浏览，点击适应视图查看全貌。
- 轮询按节点更新，保留缩放、平移、搜索输入、展开状态和已加载的子项页码。无变化时不重建关系图。单次读取最多展开 240 项、24 层，达到保护上限时提示收起分支或搜索定位。
- 历史版本使用当时保留的范围数据。当前事项已进入其他版本或修订时，可以单独查看历史信息；当前记录已不存在时不提供无效跳转。

页面权限标识为 `lineage`，可在「角色与权限」中独立配置。新项目的默认角色包含此页面；已有项目的角色权限不会自动扩大，需要项目管理者明确勾选。只有谱系权限的用户可查看元数据概览，查看正文和处理事项仍需需求池、验收与交付或项目版本权限。创建操作另外检查 `requirement.create`。

## 关系来源

| 关系 | 字段 | 行为 |
| --- | --- | --- |
| 子需求 | `parent_task_id` | 在需求详情中创建，独立评审、开发、交付和验收 |
| 关联 Bug | `parent_requirement_id` | 保留原测试、修复、复测流程 |
| 追加迭代 | `iteration.parent_task_id` | 保留原已验收需求追加迭代流程 |

关系只使用真实记录，不从标题或 Agent 推断。子需求创建时验证同项目、上级为需求、创建权限和页面权限；默认继承仍在进行中的上级版本，否则使用项目默认版本。已保存的上级不能通过内容编辑更换，也不能将子需求或已有子需求的上级转换为 Bug。父子需求的生命周期互不驱动。

## 查询与兼容

```text
GET /api/projects/{id}/lineage/versions?page=1&page_size=12
GET /api/projects/{id}/lineage?version_id={versionID}&page=1&page_size=3&q={keyword}
GET /api/projects/{id}/lineage?version_id={versionID}&parent_id={taskID}&page=1&page_size=4
```

计数和分页在只读事务中完成，查询有超时保护；参数使用绑定值，跨项目父引用不会连接，异常循环按最小 ID 切断一条边。接口需要当前项目的 `lineage` 页面权限，不授予原任务或版本管理 API 的访问能力。

无需数据库结构迁移。新增父子关系保存在任务及版本范围的 JSON 中；旧客户端不传该字段的内容编辑会保留既有关系。**旧服务端写入器不认识这个字段，创建子需求后不能直接回退旧服务端并继续写入**，否则后续保存可能丢失关系。发布和回退应使用支持该字段的写入器，或先准备兼容补丁。

验证包括 `make test`、SQLite 范围与历史快照测试、服务端独立权限与权限撤销测试、子需求创建及兼容编辑测试、布局不重叠测试，以及隔离环境的桌面与手机交互检查。真实业务数据的视觉验收与生产发布另行进行。
