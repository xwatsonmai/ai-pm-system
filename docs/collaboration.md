# 异步环境排查协同（第一版）

平台 Agent 可以在项目问答中创建只读排查任务，开发 Agent 使用自己的环境权限调查，再通过开发 MCP 回传结果。生产凭据不进入平台。当前支持对话发起的协同；需求/Bug 的开发验收流程保持独立。

## 用户流程

1. 用户说明线上现象和环境。平台 Agent 先利用项目、代码和已有证据分析；需要环境证据时调用 `create_collaboration`。
2. 工具持久化任务后立即返回。平台给出阶段性回答、任务 ID 和待认领状态，本次运行结束。用户可以继续聊天或关闭网页。
3. 来源消息下展示排查状态、最新进展、详情和取消入口。未认领不会显示为正在排查。
4. 开发 Agent 通过 MCP 认领、汇报和提交调查结果。
5. 后台 worker 等待原会话空闲，继续同一 Pi 会话，并结合最新消息追加一条带“协同排查结果”标识的 Agent 回答；不会创建虚假的用户发言。
6. 其他会话的新结果显示未读标识。已打开会话的消息更新保留草稿、选区和历史滚动位置。未读状态保存在当前浏览器、当前用户和项目的 localStorage 中。

## 对话中查询和取消

普通项目问答向平台 Agent 开放 `get_collaborations` 和 `cancel_collaboration`，无需用户切换到任务卡片：

- 用户问“搞定没有”时，Agent 调用 `get_collaborations` 读取当前会话的最新协同；可传 `collaboration_id` 查看指定任务，省略则列出当前会话全部协同。返回状态、认领租约、带时间的进展、阻塞说明、结果、续答状态和查询时间 `as_of`。未认领或租约过期不能解释成正在排查，调查结束也不代表故障已修复。
- 用户明确说“不用查了”时，Agent 查询定位后调用 `cancel_collaboration`，必须传明确的 `collaboration_id`。目标明确时直接取消；多个任务且指代不清时先澄清。重复取消安全，已有结论保留，不会新增取消记录或重建任务。
- 工具从持久化的当前问答获取用户身份和会话范围，并重新核验项目权限、会话是否删除。即使知道 ID，也不能查询或取消其他会话、其他用户或其他项目的协同。自动续答不开放这两个工具。
- 取消撤销认领凭据，拒绝迟到进展和结果，停止后续自动续答，并触发工作列表变化通知。本地正在执行的排查仍需开发宿主收到通知或再次查询后协作停止；平台不会声称已经终止本地进程。

## 继续调查与历史结果

“查到哪了”等进度查询先读取实时状态，不创建新任务。“继续刚才的问题”“重新查一次”“配置已恢复，请再试”等是续查请求：目标和环境明确时，先查询原任务；尚未结束的同类任务继续复用，已完成的调查则创建新一轮只读协同。会话已有协查时，服务端要求本轮先成功调用 `get_collaborations`，未查询或查询失败时拒绝创建，模型需先查询后重试。新任务摘要包含旧任务 ID、原取证时间、本轮补充和待重新核验的问题，旧调查及其结果保持不变。创建成功后报告新任务 ID 和待认领状态，不等待或声称本地已开始执行。

`cannot_access`、`inconclusive` 都是历史取证结论，不能证明当前仍无法访问。桌面客户端修改环境说明不会自动重新下发已完成的任务；新一轮执行使用执行端的最新环境说明，凭据仍留在本地。平台不能仅因旧结论或预测再次失败而拒绝用户已明确提出的续查，也不要求用户再次确认访问条件。

取消的任务不自动重建，必须由用户明确要求重新排查；多个任务指代不清时先澄清。自动结果续答仍禁止递归创建协同，该限制只适用于该次自动续答，不阻止后续用户发起新调查。

## 状态与可靠性

调查状态：`pending`（待认领）、`investigating`（排查中）、`blocked`（阻塞）、`completed`（已返回结果）、`canceled`（已取消）。

调查结果包含 `confirmed`、`inconclusive` 或 `cannot_access`，以及结论、脱敏证据、实际核查环境、取证时间、部署版本和未确认项。无法确认时应如实回传；调查完成不代表故障已经修复或发布。

续答状态独立存储：`pending`、`running`、`delivered`、`failed`、`skipped`。模型不可用不影响调查结果保存；页面提供“重试补充回答”。一般执行失败最多自动尝试 3 次，人工停止后不自动重试。配置缺失直接提示修复后重试。

- 认领租约为 10 分钟。建议开发宿主每 2–3 分钟通过 `collaboration_report` 汇报/续期；过期可重新认领，旧凭据不再有效。
- 所有 MCP 写操作携带唯一 `request_id`。网络重试使用完全相同的参数和 ID；同 ID 不同内容被拒绝。提交前读取最新 `version`。
- 提交结果在同一数据库事务中保存调查状态、不可覆写的结果、幂等回执和续答任务。
- 每个结果固定对应一个续答 Run ID。模型调用允许重试，但只更新同一条可见回答。若已保存成功回答而回执未完成，恢复时仅补记送达。
- 服务重启恢复待续答任务；当前实现沿用单 Go 服务实例的运行管理，不支持多个平台进程同时调度同一数据库。
- 同一会话的用户输入与自动续答共用准入锁和执行锁。当前轮次未结束时，结果在后台等待。
- 会话删除、协同取消或发起人失去项目权限后停止自动续答。已删除会话不会被迟到结果恢复。
- 自动续答只开放项目上下文和 Git 只读工具，不再发起协同，避免无限派单。

## 开发 MCP 与订阅

工作列表资源：`ai-pm://projects/<project_id>/work`，通过 `resources/list` 发现实际 URI。

资源正文与 `work_list` 相同，包含 `tasks` 和 `collaborations` 两个数组。返回可领取的事项以及当前授权用户正在处理的事项；其他人仍持有效租约的协同不会作为可领取工作返回。租约过期的协同可能仍显示排查中，客户端依据 `lease_until` 判断是否可重新认领。

对于协议 **2026-07-28**，使用 `subscriptions/listen`，将该 URI 放入 `notifications.resourceSubscriptions`。服务端确认订阅后，在列表变化时发送标准 `notifications/resources/updated`。按版本要求携带协议元数据及 HTTP 头，建议由 SDK 生成。旧版客户端仍可使用普通工具查询；本版未实现旧协议独立 GET SSE 订阅。

```json
{
  "method": "subscriptions/listen",
  "params": {
    "notifications": {
      "resourceSubscriptions": ["ai-pm://projects/<project_id>/work"]
    }
  }
}
```

上面仅展示订阅参数，不是完整 JSON-RPC 请求。

客户端必须在订阅确认后读取一次 `work_list`；收到变化通知后重新读取；断线重连后重新订阅并读取。通知是变化提示，业务数据库是事实来源，不依赖通知重放保证不漏任务。未变化的快照不会重复通知；服务端也会检查租约到期引起的列表变化。

订阅客户端必须保持运行。MCP 通知不会自行启动外部 Agent；“收到通知 → 调度开发 Agent”由宿主或插件负责。本版提供服务端订阅及普通拉取能力，未安装本地常驻程序，也未修改开发者现有 Agent 宿主。仅支持工具调用的客户端可在开工时调用 `work_list`。

## 权限与共享范围

- 协同 Brief 是显式分享给项目开发方的必要排查摘要。不要复制无关私人对话、凭据或完整敏感日志。
- 开发 MCP 只能读取当前 OAuth 授权项目的协同；返回值去除原会话、原消息和会话所有者标识，不能据此读取私人聊天。
- 发起人通过 Web 读取自己创建的协同，取消任务或重试续答。自动回答继续继承原会话归属。
- 协同描述、日志和开发方结论均是资料，不能修改 Agent 权限。协同仅授权只读排查；重启、发布、改配置和写业务数据需遵循本地明确授权。
- 撤销 OAuth 授权、关闭个人 MCP、移除项目成员或访问令牌过期后，新请求立即失效，已有通知连接在下一次变化或权限检查时关闭（最长约 5 秒）。

## 实现入口

- `internal/domain/collaboration.go`：协同、结构化结果和续答任务。
- `internal/app/collaboration.go`：权限、认领租约、幂等、版本控制和统一工作列表。
- `internal/storage/sqlite/collaboration.go`：事务和持久化。
- `internal/agent/collaboration.go`：后台调度、恢复、取消与重试。
- `internal/server/mcp.go`：工作列表资源、标准订阅通知和开发工具。
- `internal/server/collaboration.go`：发起人 Web API。

验证使用临时 SQLite、官方 MCP Go 客户端、真实 Pi SDK 加本地模型桩，以及 Playwright 界面检查；不会访问生产环境或付费模型。真实开发宿主的订阅和自动执行支持仍需单独接入验收。
