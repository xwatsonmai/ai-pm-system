# 私有仓库与项目成员

## 接入流程

在创建项目或项目设置中填写仓库地址，选择认证方式，点击「测试连接」。成功后选择真实分支，再保存。没有代码的空仓库可以先填写预期分支。测试连接执行只读 `git ls-remote --symref`，不会创建项目、提交或推送代码；首次配置保存后自动在后台建立平台自己的裸仓库镜像，无需再点「同步仓库」。先创建项目、之后补填仓库也会自动触发首次同步。

界面依据服务端实际任务显示「正在同步」，刷新页面不影响任务；完成后自动显示代码列表，失败时保留已保存的项目、显示错误并提供「重试同步」。修改默认分支后，或首次同步失败后再次保存配置，也会重新触发同步。后台、手动和定时同步共用项目锁，单次最多两分钟，不重复拉取；`-sync-interval 0` 只关闭定时同步，不影响保存时触发的同步。服务重启会中断未完成的任务，可手动重试，或由下一次定时同步恢复。

| 方式 | 配置与行为 |
| --- | --- |
| 公开仓库 | 不使用服务器凭据、SSH agent 或全局 Git 认证配置 |
| HTTPS Token | 仓库平台要求的用户名与只读访问令牌；也支持内网 HTTP 地址，建议 HTTPS |
| SSH 密钥 | 专用无口令私钥与经管理员核验的 known_hosts 主机公钥；也可生成 Ed25519 密钥，仅返回公钥供添加为只读 Deploy Key |
| 服务器已有凭据 | 本机免登录模式可用；统一登录模式仅兼容原项目原地址，不能用共享服务器身份创建新项目 |

登录模式下新项目只接受远程 HTTP(S)/SSH 地址；已有本地仓库可以继续使用。创建后仓库地址仍不可替换，可更新分支或认证配置。凭据留空会保留原值；切换为公开方式会解除项目的凭据关联。SSH 口令密钥暂不支持，主机身份不匹配会拒绝连接，不自动信任扫描结果。

测试失败显示认证/权限、仓库不可见、网络、证书或 SSH 主机身份错误；部分 Git 服务会统一隐藏不存在与无权访问的区别，因此不能仅凭错误精确区分二者。连接成功只证明可读，不证明令牌没有写权限；请在仓库平台授予只读范围。

## 项目访问

新建项目的登录账号为项目管理员。角色包括开发者、产品和管理员；三者拥有相同的业务操作能力，管理员额外管理成员。成员从当前登录方式提供的成员目录中搜索：内置账号模式下是平台账号；外部登录扩展可以提供组织目录，按姓名、工号、部门搜索，无需成员预先登录工作台。

| 能力 | 开发者 / 产品 | 项目管理员 | 未分配员工 |
| --- | --- | --- | --- |
| 查看、协作、验收、附件、代码与 Agent 问答 | 可以 | 可以 | 拒绝 |
| 编辑项目资料、仓库认证与分支 | 可以 | 可以 | 拒绝 |
| 搜索成员目录并添加/移除成员、分配角色 | 拒绝 | 可以 | 拒绝 |
| 开通个人 MCP 并授权已加入项目 | 可以 | 可以 | 可开通，不能授权未加入项目 |

平台管理员只能通过平台设置管理所有项目的成员；访问业务项目和授权 MCP 也需要项目成员关系。成员移除后，Web 及 MCP 后续请求立即失效。项目至少保留一位管理员；创建者身份仅作记录，不会绕过移除或降级后的权限。

旧项目负责人映射为管理员，旧成员映射为开发者。原先无负责人的共享项目不再对所有登录用户开放；平台管理员需先在平台设置为其分配成员。免登录本地模式仍由本机管理员管理全部项目。

模型配置和默认模型选择已移到平台设置，仅平台管理员可读写。项目资料无法替换成员关系或配置自己的 Agent 模型。开发 MCP 使用个人 OAuth；正式登录模式停用旧项目令牌，详情见 [权限与 OAuth](access-oauth.md)。

## 存储与运行

- 仓库秘密使用 AES-256-GCM 加密，密文在独立的 `repository_credentials` 表中；认证附加数据绑定记录 ID 与所有者。项目 JSON 只关联凭据 ID，不保存秘密。
- 主密钥为数据目录中的 `repository.key`，权限 `0600`，不进版本库。备份必须同时保留 SQLite 与该文件；存在凭据但密钥缺失时，启动失败，不自动生成替代密钥。
- Token 通过临时 Git credential helper 从私有文件读取，不写到 URL、命令行参数或 Git 配置中；helper 由 `/bin/sh` 读取，无需临时文件的执行权限，兼容容器 `/tmp` 的 `noexec` 挂载。SSH 临时私钥/known_hosts 只在操作期间存在。目录权限 `0700`，文件 `0600`，完成后删除。
- 显式凭据模式关闭机器 Git 凭据、URL 重写和 HTTP 重定向；SSH 使用明确密钥与严格主机校验。Git 错误只返回归类后的消息，不回传可能包含秘密的原始 stderr。
- 仓库认证元信息接口仅项目成员可见，提供用户名、公钥、known_hosts 与“已配置”状态，不返回 Token 或私钥。
- `storage.Store` 抽象新增密文记录与用户目录读写；SQLite 迁移为新增表/字段，后续 MySQL 适配保持相同接口，密文使用 BLOB 类型。模型 API Key 沿用现有存储，不在本次仓库凭据加密范围内。

实现依据：[Git 凭据与 AskPass 文档](https://git-scm.com/docs/gitcredentials)、[OpenSSH 主机校验配置](https://man.openbsd.org/ssh_config#StrictHostKeyChecking)。

## 验证范围

自动化覆盖：真实 Git HTTP Basic/Token 连接、分支发现、clone/fetch/read，真实 OpenSSH 公钥认证与 clone、拒绝未知主机；密文落库、密钥重载、记录绑定、防止丢失密钥后静默重建；多账号列表过滤与项目/任务/附件/代码/Agent/凭据/MCP 令牌接口越权；移除成员、旧项目隔离、三个角色与平台模型修改限制。

首次同步回归覆盖：带仓库创建、后补仓库、失败保留项目与错误、请求取消后后台继续、同步互斥、未同步时不误报分支名。浏览器验证脚本 `internal/web/repository-sync.browser-check.mjs` 使用临时 SQLite、本地真实 Git 和受控 clone 门闩，检查刷新后同步状态、代码列表自动出现、输入草稿保留、失败重试与手机布局；构建 `bin/ai-pm-auto-sync-check` 后运行，可用 `AI_PM_QA_NODE_MODULES` 指定 Playwright 包目录。结果保存于 `test-results/repository-sync-ui/`，不调用真实模型。

SSH 集成测试使用系统 `/usr/sbin/sshd` 和临时密钥，仅监听随机 loopback 端口；没有 sshd 的环境跳过该集成测试。浏览器验收使用独立的本地 OAuth/Git 测试服务和测试数据，未使用或更改真实业务仓库凭据。

## 容器内的 Token 认证

部署镜像的 `/tmp` 以 `noexec` 挂载，不能直接执行写在 `/tmp` 里的 AskPass 脚本，否则 Git 会因 `Permission denied` 拿不到凭据。平台改用 Git 的 shell credential helper：由可信的 `/bin/sh` 读取权限为 `0600` 的临时文件，因此可以保留 `/tmp noexec`。认证辅助程序无法运行时会单独报错，不会被当成令牌错误。

回归测试使用真实的 `git http-backend` 和测试凭据，在只读、非 root、`/tmp noexec` 的容器配置下验证：正确的令牌能发现分支，错误的令牌会被拒绝。
