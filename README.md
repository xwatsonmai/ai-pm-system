# 智驱 · AI 原生需求管理系统

智驱是 AI 原生驱动的新一代需求管理系统：Go 后端、SQLite 持久化、Pi SDK 平台 Agent、开发 MCP 和中文 Web 工作台。

围绕「人提出和确认需求 → 开发 Agent 认领并实现 → 平台 Agent 理解项目、跟进变化 → 人验收」协作。开发 Agent 在原有 IDE 或终端里工作，通过 MCP 接入本平台。

## 启动

需要 Go 1.26.2+、Node.js 22.19+、npm 和 Git。在仓库根目录执行：

```sh
npm ci --prefix runtime --ignore-scripts
go run ./cmd/server
```

打开 <http://127.0.0.1:8090>。前端由 Go 内嵌提供，不需要单独启动前端服务。

编译后运行：

```sh
go build -o bin/ai-pm ./cmd/server
./bin/ai-pm -addr 127.0.0.1:8090 -data ./data
```

请从仓库根目录运行，或用 `-pi-worker /绝对路径/runtime/worker.mjs` 指定 Pi 入口；运行时仍需保留 `runtime/node_modules`。

参数：`-data` 指定数据目录；`-sync-interval 5m` 设置 Git 观察周期，设为 `0` 可关闭定时同步。默认监听本机回环地址；配置登录（`auth.json`）后允许远程监听。服务器部署见 [自部署](docs/self-hosting.md)。

## 登录

没有 `data/auth.json` 时为本机免登录模式，只能监听回环地址。部署给团队使用时，在 `auth.json` 中选择登录方式（也可通过 `-auth-config` 指定配置文件）：

- **内置账号**：`{"provider": "local", "public_url": "http://your-host:8090"}`，模板见 `config/auth.local.example.json`。首次启动时日志会打印初始化口令，用它创建首位平台管理员；之后由平台管理员在「平台设置 → 平台账号」中创建、重置、停用账号。
- **外部登录扩展**：接入企业已有的身份认证服务，以 provider 的形式注册，见 [登录方式 · 扩展边界](docs/login.md#扩展边界)。

业务 API 需要登录，开发 MCP 使用个人 OAuth 授权，与登录方式无关。会话规则、账号安全策略和扩展边界见 [登录方式](docs/login.md)。

## 第一次使用

1. 创建项目，填写说明和 Git 地址，选择公开仓库、Token 或 SSH 密钥认证；也可先留空。新项目默认仅负责人和指定成员可见。
2. 点击「测试连接」获取分支，选择后保存，再点击「同步仓库」。私有仓库支持加密保存凭据、生成 SSH 公钥；详细配置见 [仓库与成员权限](docs/repository-access.md)。
3. 在「需求池」创建「迭代需求」或「Bug 修复」，编写图文需求、上传截图/文档并补充逐条验收条件，确认后进入「待认领」。
4. 在独立菜单「我的 MCP」开通个人 MCP，添加服务地址到开发客户端，通过 OAuth 登录并确认授权项目。
5. 开发方提交确定的代码版本、实现说明、测试情况和未验证内容后，需求进入「测试中」，产品测试通过后进入「待上线」。测试问题以关联 Bug 跟进，全部解决或关闭后再复测，详见 [测试与关联 Bug](docs/testing-bugs.md)。实际发布后登记上线版本、环境和结果，才进入「待验收」。
6. 在「验收与交付」按需求修订、代码版本和环境逐项确认。多个事项可整理成验收包；验收结果仍逐项记录。

项目成员可以同时担任产品、开发、测试和管理员角色。需要某人处理的事项会出现在「我的待办」，也可以推送到企业微信：通过、确认这类操作在卡片里直接完成，需要填写内容时打开待办页面，电脑和手机都能用。没有专职测试的团队不用设置测试角色，测试待办会发给产品。配置和渠道扩展见 [待办与消息推送](docs/notifications.md)。

平台 Agent 的模型需要单独配置：由平台管理员在「平台设置 → 模型配置」填写提供方、模型 ID、API Key；自定义模型服务还需填写完整 API 基址和 API 类型。保存后，在平台设置中选为默认模型；所有项目统一使用此配置。支持 OpenAI Completions、OpenAI Responses 和 Anthropic Messages 协议；具体模型和工具调用兼容性取决于服务商。

未配置模型时，项目、事项、Git 和开发 MCP 仍可使用。配置后，需求变化、工作汇报和已观察分支变化会触发分析；可手动整理需求、调查 Bug、询问项目情况或停止运行。

## 需求池与文档编辑

需求描述支持标题、列表、表格、代码块、正文插图和附件链接。创建与编辑共用文档工作区，可粘贴截图、拖入文件、预览正文并恢复当前浏览器的草稿。附件随需求持久化，需求分析会读取图片及文档正文。具体格式、限制、修订兼容与验证方式见 [需求池与混合文档](docs/requirements.md)。

项目问答也支持创建：Agent 识别到可跟进的需求或疑似 Bug 时主动展示创建建议，用户点击「创建并评审」或回复同意后保存。明确要求创建时直接整理对话和相关附件、保存到需求池，后台进行独立评审，有结论后标记「待确认」；评审失败不影响已保存内容。详见 [问答转需求](docs/conversations.md#从问答创建需求或-bug)。

## 项目问答与附件

左侧「我的对话」按当前用户和项目展示会话历史，点击可继续追问。「新会话」立即切换到空白窗口，发送第一条消息后才保存记录；平台通过 Pi SDK 根据首条用户消息生成标题。命名失败时使用首条消息摘要，不影响正常回答。会话归属、旧记录兼容及验证说明见 [对话历史](docs/conversations.md)。

页头与输入区固定，消息区独立滚动。会话行可手动重命名或删除，手动名称优先于 AI 命名；删除前需确认，删除正在回答的会话会同时停止生成。

输入框使用 **Enter 发送、Shift+Enter 换行**，中文输入法组合输入期间不会触发发送。可点击「添加附件」、粘贴剪贴板中的图片/文件，或将文件拖入输入区；附件会显示预览、名称、大小和移除按钮，也可只发送附件。上传或提交请求失败时，当前页面的草稿和附件会保留。

支持 PNG、JPEG、GIF、WebP 图片，PDF、DOCX，以及 UTF-8 文本和代码文件。每条消息最多 6 个附件，单个不超过 10 MB、合计不超过 20 MB。图片作为图片内容传入 Pi；文档提取正文，单文件最多前 4 万字，PDF 最多前 50 页，单次文档正文合计不超过 8 万字。截取会在附件和模型输入中标明。扫描版 PDF 无可读文字时会提示改传图片；旧版 DOC、表格和其他二进制格式暂不支持。

图片需要模型具备视觉能力；自定义 API 的模型还需在模型配置中勾选「自定义模型支持图片输入」。附件原文件、元信息和提取正文存储在 SQLite，发送后可从对话记录下载。移除待发送附件只取消本次选择；草稿不跨页面刷新保存。

平台 Agent 回复支持 Markdown 标题、列表、加粗、代码块、表格、链接和引用。回答通过 SSE 实时推送新增文字，连接异常时回退轮询并自动重连。流式输出与后台更新只调整发生变化的回复节点，保留输入框、草稿、焦点和历史阅读位置；未变化的结果不重建页面。Markdown 解析与净化库内嵌在 Go 服务中，不依赖浏览器访问外部 CDN。实现与验证见 [对话渲染与刷新](docs/chat-rendering.md)。

## 本版功能

| 能力 | 当前实现 |
| --- | --- |
| 项目 | 多项目、一个项目一个仓库、开发者/产品/管理员角色与成员目录搜索 |
| 需求池 | 迭代需求/Bug 修复、富文本图文描述、文档附件、浏览器草稿、优先级、验收条件、修订号和工作记录 |
| 生命周期 | 创建并保存 → 需求评审 → 待认领 → 处理中 → 测试中 → 待上线 → 待验收 → 已验收；支持交接和退回 |
| 开发 MCP | 17 个工具，个人 OAuth 授权、实时项目成员校验、并发认领控制、请求幂等、修订校验、增量事件和工作列表资源订阅 |
| 环境排查协同 | 平台异步派单，本地开发 Agent 认领和回传，结果由后台队列驱动原会话主动续答 |
| Git 观察 | 裸仓库镜像、默认分支和已关联开发分支、提交记录、文件读取、搜索与差异工具 |
| 平台 Agent | Pi SDK 会话、流式回答、工具调用记录、独立的需求评审对话与内嵌问题表单、需求整理、进度解读、支持图片/文档附件的项目问答、Bug 初诊和建单 |
| 交付 | 提交版本与验证情况、人工逐项验收、验收包、测试/部署证据 |
| 持久化 | 业务数据与模型配置在 SQLite；Pi 原生会话文件和 Git 缓存在数据目录 |

平台 Agent 的分析不会直接覆盖人工确认的需求或代替人工验收。Bug 初诊中，新的独立问题可由 Agent 建单；原反馈已经是 Bug 时，分析附在原事项上。根因仍需开发结合复现、日志和测试确认。

项目问答缺少环境证据时，平台 Agent 可创建只读协同排查任务并结束当前回答。开发方通过 MCP 回传后，平台会在原会话补充结果，页面显示排查进展、取消、续答重试和未读提示。工作列表支持 MCP 2026-07-28 标准订阅；外部开发 Agent 的自动启动由宿主负责。详见 [异步环境排查协同](docs/collaboration.md)。

代码变更、开发自报测试、业务验收和部署记录分别保存。Git 合并和验收完成均不自动标记为上线。

## 开发 MCP

地址为 `http://127.0.0.1:8090/mcp`，采用 Streamable HTTP 和个人 OAuth 授权。在「我的 MCP」开通后，添加地址并在客户端发起 OAuth 登录，确认授权项目。

```json
{
  "mcpServers": {
    "ai-pm": { "url": "http://127.0.0.1:8090/mcp" }
  }
}
```

服务端支持动态注册与直接使用客户端 ID，不联网抓取客户端元数据、Logo 或 JWKS。登录员工、项目、回调地址及 PKCE 仍会校验。每个连接只授权一个项目；可在个人 MCP 页面撤销连接或关闭全部授权。正式登录模式不再接受历史项目令牌；免登录本地模式保留旧令牌兼容。

产品可通过 MCP 对话创建需求和 Bug、上传附件、补充或确认评审、管理里程碑和查看项目时间线，无需先认领。每条需求强制归入当前里程碑，无当前时自动创建，结束前持续追加；当前只开放一个进行中里程碑。写操作须有用户明确要求，保留实际员工与历史。

完整工具与流程见 [产品与开发 MCP 说明](docs/developer-mcp.md)，角色、成员目录和升级规则见 [权限与 OAuth](docs/access-oauth.md)。

## 架构与存储替换

```text
Web / 产品与开发 MCP
       ↓
Go HTTP + 应用服务 ────────── Git 只读适配器
       ↓                         ↑
storage.Store 接口          平台项目工具
       ↓                         ↑
SQLite 适配器             Go 运行管理 → Node 薄桥接 → Pi SDK
```

`internal/domain` 和 `internal/app` 不依赖 SQLite 驱动或 SQL 方言；数据库相关代码集中在 `internal/storage/sqlite`。状态变更、版本比较、事件追加和幂等回执是同一个存储事务。

未来接入 MySQL：实现同一个 `storage.Store` 接口，提供 MySQL 建表/迁移和 SQLite 数据迁移，运行存储契约与业务测试，再调整启动入口的数据库装配。**本版尚未实现 MySQL 适配器，不能仅修改连接字符串完成切换。** 更多细节见 [架构说明](docs/architecture.md)。

## 数据与运行边界

默认数据在 `data/`，已加入 Git 忽略：

- `ai-pm.db`：项目、事项、事件、证据、分析结果、附件原文件及正文、模型配置、登录状态和令牌摘要。
- `repository.key`：仓库凭据的 AES-GCM 主密钥，权限 `0600`；必须随数据库一起备份。
- `auth.json`：可选的登录配置（内置账号或外部登录扩展），文件权限应设为 `0600`。
- `repos/`：平台自己的 Git 裸仓库镜像。
- `snapshots/`：按项目和完整 SHA 缓存的只读源码快照；隔离阅读每次运行使用独立 Worker 容器。
- `pi/`：Pi SDK 原生会话和模型缓存，按项目/会话隔离。

项目可在设置中启用「隔离源码阅读」并指定分析版本。该模式使用 Pi 原生 `read/grep/find/ls`，保留业务工具，需额外安装受限 runner 与 Worker 镜像。配置、容器验收和显式回退见 [项目源码只读沙盒](docs/readonly-sandbox.md)。

关闭服务后备份整个数据目录即可保留业务与会话。运行中备份 SQLite 应使用数据库备份机制，不能只复制主文件而遗漏 WAL。模型 API Key 存储于服务端数据库，接口不回显，依靠文件权限保护；仓库 Token/私钥另行加密存储。请同时备份 `repository.key`，缺失后无法解密已有仓库凭据。

支持本地运行和 Docker 服务器部署、内置账号或外部登录扩展、平台管理员和三个项目角色。历史无成员项目需由平台管理员重新分配访问。负责人转让、GitHub/GitLab PR/CI/Webhook、自动部署、自动业务验收、向量检索和多仓库依赖图尚未实现。Git 通过定时同步观察，PR、测试和部署证据可由开发 MCP 或人工补充。

## 验证

```sh
go test -race -timeout 60s ./...
go vet ./...
npm test --prefix runtime
node --check internal/web/static/app.js
```

测试覆盖任务流转、旧修订拒绝、并发认领、交接凭据、重复请求、证据不可覆写、SQLite 重启读取、真实临时 Git 仓库、官方 MCP 客户端接入与项目隔离，以及附件上传下载、文档提取、尺寸限制和项目隔离。Pi 测试使用真实 SDK 和本地模型接口测试桩，覆盖图片/文档内容传输、工具调用、结果持久化、会话续接和停止运行；不访问付费模型。

未安装 Node.js 或 Pi 依赖时，Go 的 Pi 集成测试会明确跳过，不能将此时的测试结果当作 Agent 已联通。真实模型提供方和真实业务项目的效果需要配置后单独验证。

原始范围见 [MVP 产品方案](docs/product-plan-mvp.md)。
